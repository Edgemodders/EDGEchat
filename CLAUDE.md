# EDGEchat: notes for Claude sessions

EDGEchat is the EDGE plugin for Claude Code: skills with Cyberpunk 2077 modding knowledge, the EDGE MCP servers (REDnode's kernel server for the running game, REDcode's `redcode-mcp` for the game's files, EDGEdeck's `edgedeck-mcp` for the mod library and deploys, later EDGEmat's and the other EDGE tools'), and a few commands, in one install from this repo's own plugin marketplace. It works in EDGEkit, VS Code and the terminal. Read [docs/design.md](docs/design.md) first: it has the facts from the Claude Code docs that the design rests on, with their pages.

## Conventions

- Same as the sibling repos: commit straight to `main` in small commits and push; plain, short sentences; tables for facts; mark anything unverified.
- **Git identity:** per repo, `CyberbuildsAI` with the GitHub no-reply email (`340969962+CyberbuildsAI@users.noreply.github.com`), plus `credential.https://github.com.username CyberbuildsAI`. Push with `GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never timeout 120 git push`. Never change the global identity.
- **Do not change the other EDGE repos from here.** Needs go to their sessions (through the user) or as issues: knowledge sharing to REDagent, providing the plugin to EDGEkit, token handover to REDnode.
- **Knowledge is checked, not guessed.** Every fact a skill states about the game is checked against it through the MCP servers (`rednode` while the game runs, `redcode` offline), or marked unverified. Community sources (wiki.redmodding.org, framework docs) are written in our own words with links back, never copied.
- **Skills stay small:** a sharp `description` (it is always in context), `SKILL.md` under 500 lines, details in reference files beside it.
- **Safety in the skills:** mods never change the game's own files; deploy with EDGEdeck; nothing is written into the game folder by hand, except a REDnode package under development in `red4ext/plugins/REDnode/apps/<id>/` (user, 2026-10-23); a package can also be developed outside the game in a REDnode development folder (REDnode#16, REDnode 0.33.0; the user adds it in the launcher's Settings panel with Developer mode on), which the skills `rednode-mods`, `new-mod` and `init-project` teach from plugin 0.0.10; tools that change the game or the game folder (`api_call`, `archives_reload`, EDGEdeck's deploy, undo and remove) ask before every call, through their servers' flag, never through advice to the user; reads of the game go through `api_read`.
- **Never commit game files**, extracted game data, tokens or keys.
- **Trademarks:** the plugin says what it is (for Claude Code, for Cyberpunk 2077) and never implies endorsement by Anthropic or CD PROJEKT RED. No names starting `claude-` or `anthropic-`.
- **Releases** (asked for by the user on 2026-10-26, as EDGEmat's): `.github/workflows/release.yml` builds `EDGEchat-<version>.zip` (the plugin folder and README.txt, `tools/release/nexus-zip.mjs`), and with **Make a release** tags `v<version>` and makes the GitHub release from `docs/changelog.md` (`tools/release/notes.mjs`; add a line under **Unreleased** with each change users would notice); with **Update Nexus Mods** it keeps the Nexus page 35680 (`nexus/`, `tools/nexus/` copied from REDnode, Mod Manager Download off: a plugin, not a game mod). No release yet; the first one creates the page's main file and replaces Nexus's empty template description. Steps in docs/dev-setup.md, "Releasing". Release gate: only after every test since the last release passed.
- **Docs site:** `docs/` is published by GitHub Pages through `.github/workflows/pages.yml` (Settings > Pages > Source: GitHub Actions). `docs/index.md` is the landing page (document ledger and roadmap status); add every page to `nav` in `docs/_config.yml`. Record every tool install in `docs/dev-setup.md`, with versions and exact commands. Record every test in `docs/testing.md` when it is first run, and its result each time it runs again.
